# 去混淆像素复制优化（#91）

本次改动减少去混淆阶段的 CPU 像素复制开销，并及时释放 PNG 编码的原生缓冲区。移动设备的实际温度和耗电仍需要真机测量。

## 实现

`Image.copyRange`、`fillImageAt` 和 `fillImageRangeAt` 共用批量复制：独立缓冲区的完整行矩形一次复制，其他矩形按行复制。共享缓冲区和重叠子视图继续按照脚本原有的逐像素顺序处理，保留自复制的覆盖语义。旋转保持原有像素排列。

PNG 编码读取 `Uint32List` 子视图的有效偏移和长度，将结果复制到 Dart 字节后通过插件提供的 `freePtr` 立即释放原生缓冲区。默认脚本路径直接返回这些字节，移除后续额外复制；注入的自定义编码器仍会复制返回值，以独立于编码器／运行时的生命周期。

既有处理后图片缓存继续复用 PNG 字节；缓存命中沿用现有跳过去混淆的路径。并发上限仍为 4，编码格式和现有脚本 API 保持兼容。

## 可复现基准

环境：Windows x64、Flutter 3.41.4、Dart 3.11.4。使用生产 `Image` 类的复制代码生成独立 Dart AOT 程序，1600×2400 像素、16 个水平条带逆序复制。每次运行预热 5 遍、计时 100 遍，重复运行 5 次；计时后逐一校验全部像素并计算校验和。

> 当时使用的基准脚本 `tool/benchmark_image_copy.py` 已随 `tool/` 清理删除，下表保留测量结果。

| 实现 | 每张复制耗时中位数 | 全图校验和 |
|---|---:|---:|
| 优化前（35555ab） | 8.10 ms | 492754373 |
| 本次批量复制 | 1.58 ms | 492754373 |

该测量覆盖像素复制阶段，耗时约降低 81%。完整处理还包含图片解码、QuickJS 调用、PNG 压缩和后续显示解码。数据受主机负载、图片大小、条带数量和脚本操作影响；应在目标设备重复测量。

## 回归与后续测量

回归覆盖完整行、局部矩形、相邻像素、共享缓冲区、重叠子视图、旋转和越界操作。Windows 原生 PNG／QuickJS 测试覆盖子视图编码、脚本成功／异常／取消、运行时和回调释放，以及输出重新解码后的像素一致性。

下一轮设备测量应使用固定的本地图片和脚本，对比首次读取与缓存读取，分别记录解码、脚本、压缩耗时，峰值内存以及持续阅读的温度／耗电。随后再评估编码器、处理后缓存表示和并发策略。

## 2026-10-11 分阶段宿主测量

曾用 `tool/image_pipeline_probe.dart` 做分阶段测量：走生产图片解码、QuickJS、PNG 编码及 `modifyImageWithScript` 路径。两个固定的合成样本均为 1600×2400、16 条带逆序；每种预热一次、记录三次，验证所有输出像素，并核对插桩路径与生产路径的 PNG 字节完全一致。

> 该探针已随 `tool/` 清理删除，下表保留测量结果。

Windows x64，Flutter 3.41.4 / Dart 3.11.4。中位数如下，单位为 ms：

| 阶段 | 黑白合成图 | 彩色合成图 |
|---|---:|---:|
| 解码并读取 straight RGBA | 31.98 | 65.16 |
| 脚本 worker（含 PNG 编码） | 201.33 | 471.02 |
| 其中 PNG 编码 | 182.32 | 450.97 |
| 复用 PNG 字节后的显示解码 | 16.45 | 49.37 |
| 单独计时的完整生产处理＋显示解码 | 253.17 | 583.22 |
| PNG 大小（字节） | 3,216 | 138,436 |

原始结果见 [JSONL](data/image_pipeline_windows_20261011.jsonl)。本次是 `flutter test` 宿主测量，不能与前文 Dart AOT 的复制微基准直接比较，也不代表 Android 耗电。PNG 字节复用测量不包含磁盘读取、网络或 Flutter 图像缓存命中；worker 插桩使用现有编码器注入接口，会额外复制输出字节，因此完整生产路径另行计时。RSS 包含测试宿主、验证分配和之前样本，不能当作单张图片的内存增量。

两个样本都显示 PNG 编码占主要耗时。下一轮优先比较编码耗时、输出体积与内存；暂不据此改变并发上限或改用原始 RGBA 磁盘缓存。一张该尺寸的 RGBA 图需要 15,360,000 字节，明显大于本次 PNG 结果。
